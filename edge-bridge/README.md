# 小林工具箱 · BOSS 海投记录助手（Edge 扩展，本地桥接版）

> 安全模式：**AI 只起草，发送前请人工确认**。
> 本扩展绝不自动发送简历、绝不代聊。你的账号与聊天由你亲手控制。

## 它能做什么

在 BOSS 直聘职位详情页打开浮层面板，一键完成：

- **提取岗位信息**：公司 / 职位 / 薪资 / 地点 / JD 原文（可手动修改）
- **打招呼后自动记录（v0.2）**：在 BOSS 发送打招呼 / 系统自动打招呼后，自动把 公司 / 职位 / 薪资 / JD 记录到工具箱；同一岗位 10 分钟内只自动记一次，后端按链接去重，绝不重复入库
- **记录到小林工具箱**：复用本地 `localhost:8000` 后端的「投递记录 + JD 快照」，同一职位链接**自动去重**，不会重复记录
- **生成打招呼文稿**：按 JD 与所选简历，调用后端模板生成打招呼语，一键复制后由你粘贴到 BOSS 聊天框人工发送
- **记录管理**：面板内可见最近 5 条记录，随时删除误记条目

## 工作原理

```
BOSS 职位页 ── content.js（提取 + 浮层）──> background.js（扩展内 fetch）
     ↑                                          │ X-Bridge-Token
     └── 人工复制打招呼语、人工点击发送 ←────────┘  http://localhost:8000/api/bridge/*
```

- 自动记录：content.js 监听聊天消息列表里“自己发出的消息”（点发送后的气泡、BOSS 自动打招呼），自动提取上下文并入库；职位详情页直取页面，聊天页读取职位卡片/链接，必要时复用最近访问过的职位页缓存（2 小时内），识别不到时会跳过并提示
- 内容脚本无法跨域，所有请求由后台 Service Worker 发起（MV3 `host_permissions` 已授权 `http://localhost:8000/*`）
- 后端新增 `/api/bridge/*` 路由，写操作要求请求头 `X-Bridge-Token`，防止本机其他进程乱写数据

## 安装

1. 启动后端：`cd E:\job3.0\backend && .venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000`
2. 打开 Edge，访问 `edge://extensions`
3. 打开右上角「开发人员模式」
4. 点「加载解压缩的扩展」→ 选择本目录 `E:\job3.0\edge-bridge`
5. 打开任意 BOSS 直聘职位页（如 `https://www.zhipin.com/web/geek/job?id=xxx`），点右下角绿色 📦 按钮

## Token 配置

- 后端默认 `BRIDGE_TOKEN=job3-bridge-local-2026`（见 `backend/app/core/config.py` 与 `backend/.env.example`）
- 扩展默认使用同一值；若你在后端 `.env` 改了它，请在扩展弹窗（工具栏图标）里同步修改并保存

## 使用流程（每个职位约 10 秒）

### 自动模式（推荐，不用开面板）
1. 打开职位详情页（此时扩展缓存岗位上下文）
2. 在 BOSS 点「立即沟通」，发出打招呼 / 第一条消息
3. 右下角自动弹出绿色提示「✅ 已自动记录：公司 · 职位」；已记录过的会提示「已记录过」且不会重复写入
4. 面板（📦）里可查看最近记录、删除误记；面板顶部开关可随时暂停自动记录

### 手动模式（面板）

1. 打开职位详情页 → 点 📦 → 面板已自动填好公司/职位/JD
2. 选择要用的简历 → 点「记录到工具箱（去重）」
3. 若该职位已记录过，面板会提示「已记录过（应用 #id）」，不会重复入库
4. 检查/微调打招呼语 → 「复制打招呼语」
5. 切到 BOSS 聊天框粘贴 → **人工点击发送**

## 目录结构

```
edge-bridge/
├── manifest.json      MV3 清单（BOSS 站点注入 + localhost 授权）
├── content.js         BOSS 页面注入：提取、浮层面板、打招呼后自动记录、记录交互
├── background.js      桥接请求（带 X-Bridge-Token）、消息路由
├── popup.html/js      扩展弹窗：连接状态、Token 配置、快捷入口
└── README.md
```

## 说明与边界

- 记录落库为「投递记录 status=pending（已记录/待沟通）」，不会自动把简历状态改成「已投递」；你可在工具箱里手动推进状态
- JD 原文与打招呼文稿存档在 `job_snapshots` 表，可随时回溯该职位投递时的原始 JD
- 自动记录只在“你自己发出的消息”出现后触发，只写入本地工具箱，绝不自动发送消息 / 简历
- 若在纯聊天页发送且页面没有职位卡片、也从未打开过对应职位页，扩展会提示「未能识别岗位」并跳过，避免记错公司
- 不做：自动发送简历、自动聊天、绕过 BOSS 风控的任何行为
